Recipes

Copy and paste

Short recipes to copy and paste. Every section starts with a block that sets what it needs (the environment, the repository, the data paths, the run folder), so each section works on its own. Every path is a variable set in that first block: change them there for another machine (the ones below are the development machine's; on the 64-core server ERA5 is /data/ERA5/Europe). Background, design and checks: the setups' READMEs (IDEAL/, NEAB/, DKm/) and pygetm-config's docs/nesting.md.

How a run is made (all setups but IDEAL's own experiments): make_master.py writes a master file from the layout and the level bathymetries, pygetm-config nest turns it into one run script per level and a launch script, the launch runs all levels as one MPI job, and nesting-m2 fits M2 afterwards. To change a run, change the master (the make_master.py options), not the generated scripts. Each level writes into $RUN/out/<level>/.

Runs of several days belong on the 64-core server (64 cores; the development machine has 20): tools/setup_machine.sh HOST brings the code and the environment there, TPXO9 is /data/TPXO9 and the inputs that live only in the development machine's /data/kb have to be copied. For scale, on the 64-core server: DKm 8 days about 3 h (two runs side by side), NEAB coarse 31 days about 30 min with 60 processes.

Checked on 19 November 2026 on the development machine: every block run in a shortened form (hours instead of days), except section 6 (it needs CMEMS access), the sbatch submission in section 8 (no Slurm there; the job file was written) and the bathymetry download in section 11.

IDEAL

An idealised nest of three Cartesian levels (channel, shelf, strait) with an analytic depth: no external data, a few minutes on 5 cores. A good first run, and a check of the installation.

conda activate pygetm-nesting; export PYTHONNOUSERSITE=1
NESTING=~/source/repos/bolding/pygetm-nesting   # the repository
DATA=/data/kb                                    # runs and boundary files
cd $NESTING
RUN=$DATA/IDEAL/runs/howto_cfg
OWN=$DATA/IDEAL/runs/howto_own                  # IDEAL's own models

Through pygetm-config (a closed basin driven by a wind stress: pygetm-config cannot express IDEAL's tide):

python IDEAL/scripts/ideal_bathymetry_files.py IDEAL/config/ideal.yaml --out $RUN/bathymetry
python IDEAL/config/pygetm-config/make_master.py --out $RUN
pygetm-config nest $RUN/ideal.yaml --out $RUN/gen
$RUN/gen/run_ideal.sh --stop 2000-01-01T06:00:00 \
    --data-root IDEAL_BATHYMETRY=$RUN/bathymetry --data-root OUTPUT_FOLDER=$RUN/out

IDEAL's own models (IDEAL/models/ideal2d.py, ideal3d.py): the tide, the 3D experiments, the sluice and the fjord. run_ideal.py builds the launch, runs it and summarises volume, heat and timings; arguments after -- go to every level.

# 2D, the tide
python IDEAL/scripts/run_ideal.py --ranks channel=2,shelf=2,strait=1 --out $OWN/tide -- --hours 48
# 3D with temperature
python IDEAL/scripts/run_ideal.py --layout IDEAL/config/ideal3d.yaml --script run3d.py \
    --ranks channel=2,shelf=2,strait=2 --out $OWN/3d -- --hours 48

NEAB coarse, 2D tides

The North-East Atlantic–Baltic nest (5 levels), TPXO9 at the root's open boundaries, 9 processes.

conda activate pygetm-nesting; export PYTHONNOUSERSITE=1
NESTING=~/source/repos/bolding/pygetm-nesting   # the repository
DATA=/data/kb                                    # runs and boundary files
cd $NESTING
TPXO=/server/data/TPXO9
RUN=$DATA/NEAB/runs/howto_coarse

python NEAB/config/pygetm-config/make_master.py --out $RUN
pygetm-config nest $RUN/neab_coarse.yaml --out $RUN/gen
$RUN/gen/run_neab_coarse.sh --stop 2020-01-04T00:00:00 --data-root NEAB_BATHYMETRY=$NESTING/NEAB/Bathymetry/coarse \
    --data-root TPXO_FOLDER=$TPXO --data-root OUTPUT_FOLDER=$RUN/out
nesting-m2 $RUN/out --layout NEAB/config/coarse.yaml --bathymetry NEAB/Bathymetry/coarse --spinup 1

nesting-m2 writes $RUN/out/<level>/m2.npz (M2 amplitude and phase of every cell a level computes, the gauges' series) after a spin-up of one day.

NEAB with the Wadden level

The coarse NEAB levels plus the Wadden Sea (6 levels; its flats wet and dry). The time steps are 0.8 × pyGETM's CFL step per level.

conda activate pygetm-nesting; export PYTHONNOUSERSITE=1
NESTING=~/source/repos/bolding/pygetm-nesting   # the repository
DATA=/data/kb                                    # runs and boundary files
cd $NESTING
TPXO=/server/data/TPXO9
RUN=$DATA/NEAB/runs/howto_wadden

python NEAB/config/pygetm-config/make_master.py --layout coarse_wadden --cores 16 --out $RUN
pygetm-config nest $RUN/neab_coarse_wadden.yaml --out $RUN/gen
$RUN/gen/run_neab_coarse_wadden.sh --stop 2020-01-04T00:00:00 \
    --data-root NEAB_BATHYMETRY=$NESTING/NEAB/Bathymetry/coarse_wadden \
    --data-root TPXO_FOLDER=$TPXO --data-root OUTPUT_FOLDER=$RUN/out
nesting-m2 $RUN/out --layout NEAB/config/coarse_wadden.yaml --bathymetry NEAB/Bathymetry/coarse_wadden --spinup 1

DKm forced by NEAB

DKm's open boundaries from a NEAB run instead of TPXO9: NEAB writes hourly fields, nesting-boundaries samples them at DKm's boundary points (one file for the three levels with open boundaries), and DKm's master reads them (each level checks its points; the file is split per level next to it).

conda activate pygetm-nesting; export PYTHONNOUSERSITE=1
NESTING=~/source/repos/bolding/pygetm-nesting   # the repository
DATA=/data/kb                                    # runs and boundary files
cd $NESTING
TPXO=/server/data/TPXO9
SRC=$DATA/NEAB/runs/howto_fields               # the NEAB run
BDY=$DATA/DKm/boundaries/howto_neab_bdy.nc     # DKm's boundary file
RUN=$DATA/DKm/runs/howto_neab

# 1. NEAB with hourly fields (zt, U, V, u1, v1)
python NEAB/config/pygetm-config/make_master.py --fields 60 --out $SRC
pygetm-config nest $SRC/neab_coarse.yaml --out $SRC/gen
$SRC/gen/run_neab_coarse.sh --stop 2020-01-09T00:00:00 --data-root NEAB_BATHYMETRY=$NESTING/NEAB/Bathymetry/coarse \
    --data-root TPXO_FOLDER=$TPXO --data-root OUTPUT_FOLDER=$SRC/out
# 2. the values at DKm's boundary points
nesting-boundaries $SRC/out/{north_sea_baltic,danish_straits}/fields.nc \
    --like DKm/config/dkm_nested.yaml dkm_root,kattegat,belt_sea DKm/Bathymetry/nested --out $BDY
# 3. DKm reading them
python DKm/config/pygetm-config/make_master.py --boundaries $BDY --out $RUN
pygetm-config nest $RUN/dkm_nested.yaml --out $RUN/gen
$RUN/gen/run_dkm_nested.sh --stop 2020-01-08T00:00:00 --data-root DKM_BATHYMETRY=$NESTING/DKm/Bathymetry/nested \
    --data-root OUTPUT_FOLDER=$RUN/out
nesting-m2 $RUN/out --layout DKm/config/dkm_nested.yaml --bathymetry DKm/Bathymetry/nested --spinup 1

DKm's run must lie within the NEAB run's time (here 2020-01-01 to 01-09).

DKm forced by CMEMS

The open boundaries from CMEMS through ocean-prep (its own environment and CMEMS access). Not run for this HOWTO.

conda activate pygetm-nesting; export PYTHONNOUSERSITE=1
NESTING=~/source/repos/bolding/pygetm-nesting   # the repository
DATA=/data/kb                                    # runs and boundary files
cd $NESTING
SRC=$DATA/NEAB/runs/howto_fields               # any run with fields.nc (section 5): only for the points
CMEMS=$DATA/DKm/boundaries/cmems_nested
RUN=$DATA/DKm/runs/howto_cmems

# 1. the boundary points of DKm's nested levels (a text file for ocean-prep; any fields.nc with zt, U, V as source)
nesting-boundaries $SRC/out/north_sea_baltic/fields.nc \
    --like DKm/config/dkm_nested.yaml dkm_root,kattegat,belt_sea DKm/Bathymetry/nested \
    --write-points DKm/Bathymetry/dkm_nested_bdy_lonlat.txt --out $CMEMS/points_only.nc
# 2. ocean-prep: point DKm/config/dkm_bdy_cmems.yaml at those points and at $CMEMS, then
conda activate ocean-prep
run-cmems-boundaries --config DKm/config/dkm_bdy_cmems.yaml
conda activate pygetm-nesting
# 3. DKm reading them (velocities: FLATHER_ELEV; the elevation corrected for the datum)
python DKm/config/pygetm-config/make_master.py --boundaries $CMEMS/hourly_2020-01-01_to_2020-01-31.nc \
    --boundary-elevation zos_datum_corrected --out $RUN
pygetm-config nest $RUN/dkm_nested.yaml --out $RUN/gen
$RUN/gen/run_dkm_nested.sh --stop 2020-01-08T00:00:00 --data-root DKM_BATHYMETRY=$NESTING/DKm/Bathymetry/nested \
    --data-root OUTPUT_FOLDER=$RUN/out

ERA5 and 3D

ERA5 atmospheric forcing, and a baroclinic run with the initial temperature and salinity from WOA (or CMEMS: --hydrography CMEMS). The 3D route needs pygetm-nesting's hydrography provider, set by the two variables below. The same options work for DKm's make_master.py.

conda activate pygetm-nesting; export PYTHONNOUSERSITE=1
NESTING=~/source/repos/bolding/pygetm-nesting   # the repository
DATA=/data/kb                                    # runs and boundary files
cd $NESTING
TPXO=/server/data/TPXO9
ERA5=/archive/ERA5/Europe          # the 64-core server: /data/ERA5/Europe
WOA=/server/data/WOA
M=$NESTING/lib/config_providers.py
export PYGETM_CONFIG_PROVIDERS=$M:register_providers PYGETM_CONFIG_DATA_ASSIGNMENTS_DERIVERS=$M:derive_data_assignments
RUN=$DATA/NEAB/runs/howto_3d

python NEAB/config/pygetm-config/make_master.py --meteo era5 --3d --out $RUN
pygetm-config nest $RUN/neab_coarse.yaml --out $RUN/gen
$RUN/gen/run_neab_coarse.sh --stop 2020-01-02T00:00:00 --data-root NEAB_BATHYMETRY=$NESTING/NEAB/Bathymetry/coarse \
    --data-root TPXO_FOLDER=$TPXO --data-root ERA5_FOLDER=$ERA5 --data-root HYDROGRAPHY_FOLDER_WOA=$WOA \
    --data-root OUTPUT_FOLDER=$RUN/out

Each level writes daily temperature and salinity (ts.nc) next to the hourly elevation. --meteo era5 alone gives a 2D run with ERA5.

8

Processes per level, pinning, Slurm

nesting-balance divides the cores over the levels from their wet cells and a cost model; make_master.py --cores N takes them from it. --bind core pins every level to its own block of cores; --slurm also writes a Slurm job (srun --multi-prog).

conda activate pygetm-nesting; export PYTHONNOUSERSITE=1
NESTING=~/source/repos/bolding/pygetm-nesting   # the repository
DATA=/data/kb                                    # runs and boundary files
cd $NESTING
CORES=18
TPXO=/server/data/TPXO9
RUN=$DATA/NEAB/runs/howto_slurm

nesting-balance NEAB/config/coarse.yaml --bathymetry NEAB/Bathymetry/coarse --cores $CORES   # the table
python NEAB/config/pygetm-config/make_master.py --cores $CORES --out $RUN
pygetm-config nest $RUN/neab_coarse.yaml --out $RUN/gen --bind core \
    --slurm --partition short --time 02:00:00 --setup 'conda activate pygetm-nesting'
cd $RUN/gen && sbatch run_neab_coarse.sbatch --stop 2020-01-04T00:00:00 \
    --data-root NEAB_BATHYMETRY=$NESTING/NEAB/Bathymetry/coarse \
    --data-root TPXO_FOLDER=$TPXO --data-root OUTPUT_FOLDER=$RUN/out

Without Slurm, $RUN/gen/run_neab_coarse.sh starts the same run pinned with mpiexec.

Restarts

Every level writes its own restart file (restart.nc gives restart_<level>.nc); a restart written with another set of levels, windows or ratios is refused. --stop must fall on a whole root step.

conda activate pygetm-nesting; export PYTHONNOUSERSITE=1
NESTING=~/source/repos/bolding/pygetm-nesting   # the repository
DATA=/data/kb                                    # runs and boundary files
cd $NESTING
TPXO=/server/data/TPXO9
RUN=$DATA/NEAB/runs/howto_restart
A="--data-root NEAB_BATHYMETRY=$NESTING/NEAB/Bathymetry/coarse --data-root TPXO_FOLDER=$TPXO"

python NEAB/config/pygetm-config/make_master.py --out $RUN
pygetm-config nest $RUN/neab_coarse.yaml --out $RUN/gen
# the first day, saving the state at its end
$RUN/gen/run_neab_coarse.sh --stop 2020-01-02T00:00:00 --save-restart $RUN/restart.nc $A \
    --data-root OUTPUT_FOLDER=$RUN/first
# the second day, from it
$RUN/gen/run_neab_coarse.sh --load-restart $RUN/restart.nc --stop 2020-01-03T00:00:00 $A \
    --data-root OUTPUT_FOLDER=$RUN/second

Comparing with tide gauges and TPXO

The M2 amplitude at the GESLA gauges (the finest level with water at a gauge; NEAB too, with --layout NEAB/config/coarse.yaml), and M2 against TPXO9 cell by cell. The gauges need nesting-m2 first (sections 2–5), and where the tide is small (Skagerrak, Kattegat, Baltic) a week or more after the spin-up: with two days M2 and S2 are not separated. neab_vs_tpxo_m2.py fits nine constituents (M2, S2, N2, K2, K1, O1, P1, Q1, M4) and needs about a month (--stop 2020-02-01T00:00:00 in section 2); after a few days its numbers are meaningless.

conda activate pygetm-nesting; export PYTHONNOUSERSITE=1
NESTING=~/source/repos/bolding/pygetm-nesting   # the repository
DATA=/data/kb                                    # runs and boundary files
cd $NESTING
DKM_RUN=$DATA/DKm/runs/howto_tpxo/out          # section 4
NEAB_RUN=$DATA/NEAB/runs/howto_coarse/out      # section 2
GAUGES=$DATA/NEAB/runs/coarse_tides_all/base_gauges_stations.csv
OUT=$DATA/NEAB/runs/howto_compare

python DKm/scripts/dkm_gauges_m2.py --run $DKM_RUN --layout DKm/config/dkm_nested.yaml --gauges $GAUGES
python NEAB/scripts/neab_vs_tpxo_m2.py --run generated $NEAB_RUN --out $OUT

A new setup

A new nest is a layout file, the level bathymetries and a make_master.py (copy NEAB's or DKm's and change its constants). Bathymetry from GEBCO/EMODnet takes a while (NEAB coarse: about 45 minutes, once).

conda activate pygetm-nesting; export PYTHONNOUSERSITE=1
NESTING=~/source/repos/bolding/pygetm-nesting   # the repository
DATA=/data/kb                                    # runs and boundary files
cd $NESTING
LAYOUT=NEAB/config/coarse.yaml       # your layout (the format: NEAB/README.md, pygetm-config docs/nesting.md)
BATHY=NEAB/Bathymetry/howto_new

python NEAB/scripts/design_neab_hierarchy.py evaluate --config $LAYOUT --save $DATA/new_setup.pkl   # grids, active regions, time steps
# (the figure: conda activate ocean-plot; python NEAB/scripts/design_neab_hierarchy.py plot --load $DATA/new_setup.pkl --out FIGDIR)
nesting-bathymetry $LAYOUT --outdir $BATHY --run                          # <level>_bathymetry.nc per level
nesting-balance $LAYOUT --bathymetry $BATHY --cores 18                    # processes per level
# then a make_master.py for the setup (from NEAB/config/pygetm-config/make_master.py), and sections 2 and 8
